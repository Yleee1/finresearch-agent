# FinResearch 面试讲解 V2

## 一句话

FinResearch 是面向金融年报的反思式 Agentic RAG：它先把问题拆成可检查的证据槽位，在两轮硬预算内补齐证据，再用 claim ledger 审计每条结论与引用，而不是固定取 Top-K 后直接生成。

## 5 分钟陈述

1. **问题**：金融年报里的答案常跨公司、跨章节或跨表头与数据行，单次 Top-K 容易“看起来相关但证据不完整”。
2. **数据与基线**：两份 2024 年报共 519 页、881 个页码感知 chunk；V1 对比 BM25、Dense、RRF 和 Cross-Encoder，并保留冻结集与原始结果。
3. **V2 方法**：Query Analyzer 产生 route、子问题和 evidence slots；Evidence Pack 保留轮次、查询、页码和邻块；Retrieval Critic 输出覆盖矩阵，只为缺失槽位触发第二轮。
4. **答案安全**：生成后拆成原子 claim，先验引用逐字存在，再查公司、年份、指标、数值和单位；比较结论必须覆盖两端，失败最多修复一次，否则拒答。
5. **工程控制**：轮数、子查询、证据块、上下文 Token 和 LLM 调用都有硬上限；无新增证据提前停，文档内提示注入视为不可信数据。
6. **评测结果**：128 条冻结检索集上，BM25 的 Recall@5/Complete Evidence 为 79.95%/75.00%；Cross-Encoder 后为 86.46%/82.81%；再加邻块与表头扩展为 89.97%/88.28%。74 条 Agent 集上，R3/R4/R5 Strict Success 为 25.68%/24.32%/18.92%。R4 的无效二轮率达 72.97%；R5 将拒答 Recall 提到 100%，却仅回答 3/74 题。这说明反思和 critic 不是越多越好，必须用冻结消融校准。

## 三层追问

### 为什么不是固定 Top-K？

- 第一层：Top-K 只按相关性排，不保证问题里的每个公司/年份/指标都被覆盖。
- 第二层：Evidence Slot Coverage 把“够不够”变成可观测矩阵；第二轮只查缺失槽位。
- 第三层：用第二轮增量召回率和无效第二轮率判断反思是否值得；若无新增证据立即停止。

### 为什么不是无限循环？

- 第一层：默认最多两轮。
- 第二层：另有子查询、证据块、Token 和 LLM 调用上限。
- 第三层：预算耗尽返回明确拒答原因；是否增至三轮必须由冻结消融证明收益覆盖成本。

### Verifier 会不会误判？

- 第一层：会，所以不能只靠一个模型布尔值。
- 第二层：确定性槽位覆盖与模型语义判断必须同时通过，采用 fail-closed 合并。
- 第三层：分别报告 verifier false positive/negative，并在 Bad Case 中区分检索漏召回、槽位定义错和 verifier 判断错。

### 重复披露为什么会造成假阴性？

同一事实可能出现在正文、财务附注和表格多个位置。V1 只认一个 gold chunk 时，检索到等价页也会被误判失败；V2 为每个槽位标注多个 `acceptable_evidence_sets`。
